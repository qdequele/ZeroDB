# Sanctioned behavior divergences vs LMDB

Rules:
- Every entry needs a maintainer sign-off line. Agents may add entries only
  with status PROPOSED; a human flips them to APPROVED.
- The goal is no functional divergence visible through heed beyond the
  approved ones below.

Details for each entry live in the linked ADR or SPEC section; git history
keeps the original long-form notes.

| ID | Area | LMDB behavior | zerodb behavior | Status | Approved by |
|----|------|---------------|-----------------|--------|-------------|
| D-001 | Process model | Cross-process readers via lock file | Single-process only; no lock file | APPROVED | maintainer (founding design decision) |
| D-002 | File format | LMDB 0.9/1.0 on-disk formats | Own format; migration via logical dump/load | APPROVED | maintainer (founding design decision) |
| D-003 | Nested write txns | Child write txns with page shadowing | Unsupported and unrepresentable: neither the engine nor the heed adapter exposes a nested-write entry point (heed's own `RwTxn::nested` is `pub(crate)`). No consumer calls it. Nested *read* txns are supported (SPEC 04 §5). | APPROVED | maintainer, 2026-07-15; unrepresentability amendment: maintainer, 2026-07-16 (ADR-0007) |
| D-004 | DUPSORT/DUPFIXED, DatabaseFlags | Duplicate keys, integer keys, custom comparators | Unsupported; no consumer uses any `DatabaseFlags` (SPEC 00 §B.1). The DUPSORT design (ADR-0011) was parked and never merged. | APPROVED | maintainer, 2026-07-15 |
| D-005 | Writer quiescence during nested read txns | Not enforced: the write txn may mutate while nested read children are live (undefined interplay). | Enforced for Rust soundness: the shared `&wtxn` borrow at compile time plus a runtime `child_count == 0` assert on every mutation (SPEC 04 §5.2). Not observable: every consumer call site already pauses the writer. | APPROVED | maintainer, 2026-07-16. See SPEC 04 §5.2/§10. |
| D-006 | `map_size` value validation | heed rejects a `map_size` that is not a multiple of the OS page size (`Io(InvalidInput)`). | The engine accepts any `map_size ≥ 2*page_size` (page size is independent of the OS page size) and rounds the mapping length internally; reported `map_size` and MapFull use the exact value. The heed adapter re-imposes heed's check, so consumer-visible parity is exact. | APPROVED | maintainer, 2026-07-16 (ADR-0004 resolution) |
| D-007 | Fork crash case (FORK-1) | SIGSEGV in `_mdb_cursor_put` (APPEND after a same-txn clear of another db, key ≤ last; see docs/UPSTREAM-BUGS.md). | Returns `KeyExist` (SPEC 01 §S1); a crash is UB, not behavior to replicate. The oracle skips the combination until the fork is fixed. | APPROVED | maintainer, 2026-07-17 (standing directive). Guard removable once upstream fixes it. |
| D-008 | Raw bytes of a named-DB catalog record | Reading a parent DB surfaces each sub-DB's record as LMDB's `MDB_db` layout. | Same entry and key, but ZeroDB's own record layout (SPEC 02 §3.1), a consequence of D-002. Only observable by raw-reading a sub-DB record through its parent, which no consumer does. Secondary: names with an embedded NUL are valid in the engine; the adapter reproduces heed's panic for them. | APPROVED | maintainer, 2026-07-17 (standing directive). Direct consequence of D-002; unobservable to all five consumers. |
| D-009 | Concurrent `open_database` of a dropped-and-reused dbi | A fresh read txn can get a reused dbi slot from a concurrent open write txn, then fails with `EINVAL`. | Resolves `open_database` from the txn's committed catalog: returns `Ok(None)`, the correct MVCC answer. No consumer exercises this. | APPROVED | maintainer, 2026-07-17 (standing directive). zerodb returns the correct MVCC answer; no consumer exercises the LMDB hazard. |
| D-010 | `max_readers(0)` at env open | Open rejected with `EINVAL` (`Io(InvalidInput)`). | The engine accepts the open and every read txn fails with `ReadersFull`. The heed adapter re-imposes the open-time error, so consumer-visible parity is exact. No consumer passes 0. | APPROVED | maintainer, 2026-07-17 (standing directive) |
| D-011 | `MDB_envinfo::me_numreaders` semantics | A high-water mark of simultaneous readers, never decreasing (despite the header's wording). | Reproduced exactly in `EnvInfo::num_readers`; the live count is additionally exposed as `EnvInfo::live_readers` / `heed_zerodb::Env::live_readers()`. Purely additive. | **PROPOSED** — open question: redefine `num_readers` as the live count once parity obligations lapse? Not approved; parity is currently exact. | — (agent-filed; awaiting maintainer) |
| D-012 | Env data-file name | A directory env holds `<dir>/data.mdb` (+ `lock.mdb`); Meilisearch hardcodes `data.mdb` in compaction, snapshot and S3 code. | The engine's native name is `zerodb.dat`; the heed adapter creates and opens `<dir>/data.mdb` instead (ADR-0010), so all Meilisearch call sites work. Covered by `crates/heed-zerodb/tests/env_file_naming.rs` and related tests. | **APPROVED** — resolved; no standing divergence remains at the heed boundary | maintainer, 2026-07-20 (standing directive), implemented per ADR-0010 |
| D-013 | dbi handle validity after an aborted txn | A handle opened in a txn that aborts is closed; reusing it returns `EINVAL`. | `Database` is a plain value with no env-level validity flag, so reusing such a handle silently works. Maintainer decision needed: track handle generations to match LMDB's `EINVAL`, or accept the leniency? | — (agent-filed 2026-07-20, adapter-pair fuzz finding; awaiting maintainer) |
| D-014 | Custom key comparator persistence | The comparator is a per-open function pointer, never persisted; reopening with a different one silently corrupts lookups and writes. | Reproduces the hazard, with two mitigations: a conflicting in-process registration is refused (`Io(InvalidInput)`), and custom comparators are limited to named DBs. Maintainer decision: build an engine cursor-reserve for exact parity, or sanction the emulation? | — (agent-filed 2026-07-22; awaiting maintainer) |
| D-016 | `MDB_NOSUBDIR` env flag | The env is two plain files, `path` and `path-lock`. | The heed adapter refuses the flag at open with `Io(Unsupported)`; every ZeroDB env is a directory. | D-017 | Opening a file whose meta names pages beyond the file | Not checked at open; discovered as `SIGBUS` on first touch. | `open` refuses the env with `Mdb(Invalid)` on out-of-file geometry, an out-of-range root or a txnid near the reader sentinel band; reads above the snapshot's last page get a typed error (SPEC 06, SPEC 04). An invalid newer meta fails the open instead of falling back (reachable only under `NO_SYNC`). | APPROVED — stricter-than-LMDB open, no older-slot fallback under `NO_SYNC` | maintainer, 2026-09-09 (agent-filed the same day) |
| D-018 | `max_readers` / `max_dbs` upper bound | Any `u32` is accepted. | Values above `1 << 20` are refused at open with `Io(InvalidInput)` (the table is heap-allocated). Meilisearch uses far smaller values. | APPROVED | maintainer, 2026-09-09 (agent-filed the same day) |
| D-019 | Page-validation policy (ADR-0014) | Page contents are never validated; a corrupt page is undefined behavior. | Validates by default (corruption is a typed error) and offers an opt-in trusting policy, `FileTrust::trust_contents()`, that skips per-cell checks like LMDB while keeping bounds checks, so reads never leave the committed map. | APPROVED — opt-in, default validating | maintainer, 2026-09-26 (opt-in requested) and 2026-09-28 (read path) |
| D-020 | Sequential-writes fast path (ADR-0015) | Every `mdb_put` descends from the root. | Opt-in env option with per-database override: appends at a remembered rightmost leaf when the key sorts last. Results and files are identical; only speed changes. | APPROVED — opt-in, default off | maintainer, 2026-09-28 (env option plus per-database override) |
| D-021 | Configurable dirty limit (ADR-0017) | The spill threshold is a compile-time constant (131,072 pages). | Spills the same way with the same default, plus an opt-in `EnvOpenOptions::max_dirty_bytes`. Results and files never depend on it. | APPROVED — opt-in, default LMDB's | maintainer, 2026-09-30 |
| D-022 | Free-list placement (ADR-0022) | Every commit's freed-page list goes into the GC B-tree. | Each commit's freed list rides in its meta page; the GC tree is used only for overflow or readers' carried lists. On-disk format change only (format version 2); heed-level behavior and results are identical. Filed for the format record. | APPROVED | maintainer, 2026-10-05 (ADR-0022 ratification) |

### Adapter-boundary re-impositions

The engine keeps its lenient native behavior; the `heed-zerodb` adapter
re-imposes the fork's stricter behavior at the heed boundary, each with a test
in `crates/heed-zerodb/tests/boundary.rs`:

- **D-006** — `open` rejects a `map_size` that is not a multiple of the OS page
  size with `Io(InvalidInput)`.
- **D-010** — `open` rejects `max_readers(0)` with `Io(InvalidInput)`.
- **D-008 (secondary)** — a DB name with an embedded NUL reproduces heed's
  `CString::new(name).unwrap()` panic.

The adapter also applies LMDB's read-key size rule: an empty key returns
`MdbError::BadValSize` on reads (an oversized read key is still not rejected).
No consumer sends any of these inputs; the checks exist for exact fork parity.
