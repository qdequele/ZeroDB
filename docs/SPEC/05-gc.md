## §0 — What GC is and is not

- The **GC DB** (a.k.a. free DB, `FREE_DBI`) is an ordinary B+tree rooted at
  `meta.free_db.root` (SPEC 02 §3/§7). It maps a freeing-txnid to the list of
  pages that transaction retired. Its pages are normal `P_LEAF`/`P_BRANCH` pages
  (SPEC 02 §7) — there is no distinct freelist page type. What is special is the
  content of its entries and the read/write rules, which this doc owns.
- GC lets pages made obsolete by copy-on-write (SPEC 03 §5) or delete/merge
  (SPEC 03 §10) be **reused** by later write txns instead of growing the file
  forever — but only once **no live reader can still reach them** (the MVCC gate,
  SPEC 04 §4.5).
- GC is **single-writer**: only the write txn mutates the GC DB, at commit time
  (SPEC 04 §9 C1). Readers only ever *read* it (for `non_free_pages_size`, §7).

## §1 — GC DB structure and entry encoding (answers OQ1)

- **GC-1** — A GC entry is `(key = 8-byte txnid) → (value = page-id list, "PIL")`
  (SPEC 02 §7). The key is the id of the write txn that freed the pages in the
  value.
- **GC-2 — GC-key byte order = BIG-ENDIAN (OQ1 answer).** The 8-byte txnid key is
  stored **big-endian**. The GC DB is a normal memcmp-ordered B+tree (SPEC 03, one
  ordering invariant), and reclamation (§6) scans freeing-txnids in **numeric
  ascending** order ("reclaim the oldest freed pages first, up to `oldest_reader`")
  via a single forward cursor. Big-endian is the unique encoding for which memcmp
  order equals unsigned-numeric order. This is the **one** engine-internal key that
  is not little-endian (SPEC 02 §0/§7 reserved this choice to SPEC 05; ADR-0002
  OQ1). Consumer keys are unaffected (opaque codec bytes, SPEC 00 row 52).
  - *Alternative weighed:* little-endian keys (engine-native everywhere). Rejected:
    the reclaim scan would then visit txnids in a byte-permuted order and need an
    O(n) full-scan or secondary index to find "the oldest entry `≤ oldest_reader`";
    big-endian makes it a single ascending cursor walk from `first()` (GC-18).
- **GC-3** — The **value (PIL)** is a `u64 count c` followed by `c` × `u64` page
  numbers (SPEC 02 §7), all stored **little-endian** (they are ordinary engine
  integers inside a value, not sort keys). The ids are kept **sorted ascending**
  by page number (GC-4) so contiguous-run detection (GC-18) and remainder rewrites
  (GC-20) are linear scans.
- **GC-4** — Within one PIL the page ids are strictly ascending and unique (a page
  is freed at most once per txn). Across entries, a page id appears in **at most
  one** GC entry ever (INV-24): freeing is monotone — a page freed by txn `F` is
  either still free or has been reused (and removed from the GC DB) by a later txn;
  it is never listed twice.
- **GC-5** — When a PIL exceeds `max_node_size` (SPEC 02 §4.2) it spills to an
  overflow run exactly like any large value (SPEC 02 §5); there is **no** bespoke
  freelist spill format. A very large freed set (huge txn, §8) becomes one big
  overflow value under a single txnid key.

## §2 — What a write txn records

- **GC-6** — During a write txn every page that becomes obsolete is appended to the
  txn's in-memory **freed-page list** (`freed_pgs`):
  - a page COW-obsoleted (SPEC 03 §5 rule 1): its **old** pgno;
  - a split donor / merged-away page (SPEC 03 §6/§10): its pgno;
  - all `N` pages of an overflow run replaced or deleted (SPEC 03 §8, SPEC 02 §5);
  - GC DB pages the commit itself obsoletes while rewriting the freelist (§4).
  The list is **not** written to the GC DB until commit (SPEC 04 §9 C1); at commit
  it becomes (after the loose-page and self-reference handling of §3/§4) the PIL
  stored under key `writer_txnid`. A page allocated **and** freed inside the same
  txn is normally handled by the loose-page fast path (§3) and never reaches the
  GC DB.

## §3 — Loose pages (allocated and freed within one txn)

- **GC-7** — A page this txn both **dirtied/allocated and then freed** (e.g. a leaf
  COW'd this txn then merged away this txn) is a **loose page**. No *other* snapshot
  ever saw it (its only writer stamp is the uncommitted `writer_txnid`), so it is
  safe to **reuse immediately within this txn** without the oldest-reader gate.
  Loose pages live on an in-memory list (`loose_pgs`).
- **GC-8** — Loose pages are the allocation **fast path**: reusing one is O(1) (pop
  the list), needs no GC DB read, and is the **first** source `allocate()` draws
  from (§5). This is the analogue of LMDB's `mt_loose_pgs`. Reusing a loose frame
  for a new page happens only at a `&mut` op boundary (SPEC 04 TXN-43), so no
  outstanding borrow can alias it; the dirty-page store keeps the frame allocated
  (SPEC 04 TXN-41) so reuse is a rebind, not a realloc.
- **GC-9** — A loose page **not** reused by end of txn is written to the GC DB under
  `writer_txnid` at commit like any other freed page (now visible to future txns,
  gated normally). Loose status is a within-txn optimization; it never escapes.
- **GC-10 — extend-then-loose (trailing shrink).** If, at `freelist_save` (§4),
  some loose pages are the **highest-numbered pages of the file** (`pgno ==
  next_pgno − 1`, `next_pgno − 2`, … contiguously from the top) **and were never
  written this txn**, they are dropped from `loose_pgs` and `next_pgno` is
  **decreased** past them, so `last_pg = next_pgno − 1` shrinks and the file does
  not grow by holes at its tail (LMDB-style trailing-page release). Only *trailing*
  never-written loose pages qualify; a never-written loose page in the *middle* of
  the file stays a free "hole" recorded in the GC DB (INV-4 free-page exemption,
  SPEC 03 §11). This is why INV-17 scopes the high-water to written pages.

## §4 — The freelist-writes-to-itself problem and its solution

Writing the freed-page list *into* the GC DB is itself a tree mutation: it can
split GC leaves and allocate new GC pages, which **frees** old GC pages — adding
*more* entries to the very list being written. This is LMDB's classic
circularity. ZeroDB solves it with a bounded **loop-until-stable** procedure at
commit (SPEC 04 §9 C1), before any data page is flushed, with a **restricted**
in-loop allocator so the loop cannot leak GC entries.

- **GC-11 — `freelist_save` (commit step C1), loop-until-stable with restricted
  allocation.** **[Pseudocode rewritten 2026-07-16 to the ratified GC-12
  amendment (ADR-0005): drain application runs INSIDE the loop with a
  pending/re-rewrite mechanism, and the fixed point is a three-part
  condition.]** This skeleton is normative — an implementation must be
  reconstructible from it alone:

  ```
  freelist_save(txn):
      alloc_mode = GC_SAVE                       # GC-12 scope: whole procedure
      pending = keys(txn.drains)                 # every ops-drained entry needs
                                                 # its GC-20 rewrite at least once
      # (b) trailing-loose shrink FIRST (GC-10): release never-written
      #     top-of-file loose pages, decreasing next_pgno; then GC-9: the
      #     surviving ops-era loose pages join freed_pgs up front (they will
      #     be listed under writer_txnid like any other freed page).
      release_trailing_loose(txn)
      freed_pgs += take(loose_pgs)

      loop:                                      # bounded: GC-13 + a hard
                                                 # iteration guard in release
          # (a) apply_drains, INSIDE the loop (GC-20): rewrite the remainder
          #     of every pending entry / delete the fully-drained ones.
          #     These puts/deletes may themselves (i) draw from the drain
          #     pool — which re-marks the touched entry pending (save_touched)
          #     — or (ii) COW-free committed GC pages, growing freed_pgs.
          loop:
              pending += take(save_touched)
              if pending.is_empty(): break
              F = pending.pop_smallest()
              remaining = txn.drains[F]
              if remaining.is_empty():  drains.remove(F); delete(FREE_DBI, BE(F))
              else:                     put(FREE_DBI, BE(F), encode(remaining))

          # (c) this txn's own entry under key = BE(writer_txnid).
          sort_dedup(freed_pgs)                  # GC-3/GC-4
          before = freed_pgs.len()
          if before > 0:
              put(FREE_DBI, BE(writer_txnid), encode(freed_pgs), RESERVE)  # GC-2
              if freed_pgs.len() != before:
                  continue                       # the put COW-freed committed
                                                 # GC pages: PIL must grow
          # FIXED POINT = all three, together:
          #   1. no pending rewrite  (no drain-pool draw escaped a re-rewrite)
          #   2. freed_pgs stable across the put  (the write freed nothing new)
          #   3. loose settled  (GC-9: no loose page escapes unlisted)
          pending += take(save_touched)
          if not pending.is_empty(): continue    # 1 failed
          release_trailing_loose(txn)            # re-shrink loop-era loose
          if loose_pgs.is_empty(): break         # 1 ∧ 2 ∧ 3 hold: done
          freed_pgs += take(loose_pgs)           # fold survivors, go again
  ```

  Every `allocate()` inside the procedure obeys GC-12 (as amended): loose
  pages (including contiguous loose runs — the previous iteration's PIL value
  run must be re-servable or the fixed point is unreachable), the
  already-loaded drain pool (marking the entry in `save_touched`), or file
  extend — never a fresh read of the GC tree.

- **GC-12 — `freelist_save` allocation restriction (the anti-leak rule).**
  **[AMENDED 2026-07-16 by ADR-0005 during M1.5 implementation; RATIFIED —
  Quentin, 2026-07-16, standing directive, adversarial-review confirmed. The
  pre-amendment "ALL GC draws barred" text is preserved below for the
  record.]** Throughout the **entire** `freelist_save` procedure,
  `allocate()` MUST NOT **read the GC tree** (no `gc_reclaim`, no fresh-entry
  consumption). It may draw from: **(1)** loose pages (GC-7), **(2)** the
  txn's **already-loaded drain pool** — the in-memory remainders of entries
  drained during §6 reclamation — provided every entry so touched is
  **re-rewritten** (GC-20) before the loop's fixed point is declared, or
  **(3)** file extend (`next_pgno`, GC-15). The anti-leak property is carried
  by the fixed point, not by a draw ban: the loop may not exit while any
  touched entry awaits its rewrite, so the final tree state never lists a
  handed-out page (INV-22) and never drops an undrained one. Pool draws
  remain gate-correct: each pool entry passed `F ≤ oldest_reader()` when
  first loaded, and any reader that pins later pins the published snapshot
  `≥ writer_txnid − 1 ≥ F`, whose trees do not contain those pages.
  - *Why the amendment (the boundedness argument):* the in-save COW of a
    committed GC page can never reuse its own predecessor **in the same
    commit** — the `N−1` fallback meta still references it (TXN-62) — so under
    a total draw ban every commit's GC-tree writes extend the file while the
    obsoleted GC pages can only be consumed by *next*-txn ops draws. On
    steady churn, ops allocations balance ops frees, so the ban leaks the
    file upward by the per-commit GC-COW count **forever** — measured during
    M1.5 bring-up (≈ +1 page/commit; PLAN §1.5's bounded-growth acceptance is
    unachievable under the ban). The fork stays bounded the same way this
    amendment does: `mdb_page_alloc` inside `mdb_freelist_save` consumes the
    already-loaded `me_pghead` but never reads fresh FreeDB entries.
  - *Pre-amendment text (superseded):* "`allocate()` MUST NOT draw from the GC
    DB at all (no `gc_reclaim`, fresh or previously drained). It may draw only
    from loose pages or file extend. `apply_drains` runs once, before the
    loop, so a later draw from a drained entry would hand out a page the
    rewritten entry still lists as free."
  (Loose pages and file extend are safe as before: loose pages are
  this-txn-private and never listed in any committed GC entry (GC-7), and
  extend invents brand-new pgnos.)
  - *Loose-run draw inside `freelist_save` (ADR-0005 implementation note).*
    Inside `freelist_save` only, the loose draw may serve **contiguous runs**
    (`n > 1`), including a run that abuts `next_pgno` completed by extension.
    This is required for GC-13's fixed point: when the step-(c) upsert replaces
    a spilled PIL, the previous iteration's value run (this-txn-private, hence
    loose) must be re-allocatable for the rewrite — folding it into `freed_pgs`
    would grow the PIL every iteration and never stabilize. This mirrors the
    fork's same-txn `mdb_ovpage_free` unallocate path. GC-16's "loose =
    single-page only" rule continues to govern Normal-mode allocation; inside
    `freelist_save` the permitted sources are loose (incl. runs), the drain
    pool (GC-12 as amended), and extend. Loose pages still unconsumed at the
    fixed point are re-checked by a final GC-10 trailing shrink; any survivors
    are folded into `freed_pgs` and the loop resumes (each fold consumes its
    pages permanently — GC-9 holds: no loose page escapes uncommitted).
- **GC-13 — termination proof.** **[Aligned with the GC-12 amendment.]** Each
  loop iteration that does not exit strictly decreases one of three bounded,
  non-replenishable quantities: **(i)** the drain pool total (an in-save pool
  draw consumes ids; the pool is loaded during ops and never refilled in-save,
  since the GC tree is never read — GC-12); **(ii)** the committed GC pages not
  yet COW-obsoleted (a split/COW during a step-(a)/(c) put frees one into
  `freed_pgs`, which is monotone non-decreasing and bounded); **(iii)** the
  loose-fold budget (a loose page folds into `freed_pgs` at most once; the
  previous iteration's PIL value run is loose and is re-served to the next
  iteration's allocation by the free-before-allocate ordering, so it does not
  normally fold). Hence the loop reaches a fixed point — no pending entry
  rewrite, `freed_pgs` stable across the step-(c) put, no unlisted loose page
  — in finitely many iterations. (Mirrors the fork's `mdb_freelist_save`
  retry loop with `me_pghead` consumption.)
- **GC-14 — atomicity with the commit.** `freelist_save` runs **before** `write
  dirty pages` (SPEC 04 §9: C1 precedes C2). The GC DB pages it dirties are flushed
  as part of the txn's dirty set (C2) and become durable/visible **only** with the
  new meta (C4/C5). On a crash-fallback to `N−1` (SPEC 06), this txn's GC changes
  vanish atomically with the rest of the txn — GC is never half-applied.

## §5 — Allocation algorithm (answers OQ2)

`allocate(n)` returns `n` contiguous free page numbers for the current write txn
(`n = 1` for a tree page; `n = ovf_pages` for an overflow run, SPEC 02 §5).

- **GC-15 — high-water bookkeeping = `next_pgno`, persisted as `last_pg` (OQ2
  answer).** The writer tracks in memory **`next_pgno`** = the lowest page number
  never yet allocated (file high-water + 1). The meta persists **`last_pg =
  next_pgno − 1`** (SPEC 02 §3) — the **format is unchanged**; SPEC 05 uses
  `next_pgno` internally and stores `last_pg`, exactly the assumption SPEC 02 §3's
  "SPEC 04 interface note" allowed. No meta field is added (OQ2). At open,
  `next_pgno = meta.last_pg + 1`.
- **GC-16 — `allocate(n)` source order:**

  ```
  allocate(n):
      # 1. Loose pages (single-page requests only; loose pages carry no
      #    contiguity guarantee). O(1).
      if n == 1 and not loose_pgs.empty():
          return loose_pgs.pop()

      # 2. GC DB reusable pages, gated by the oldest reader (§6). For n == 1 take
      #    the deterministic single page (GC-19); for n > 1 find a reclaimable
      #    within-PIL contiguous run of length >= n (GC-18).
      #    (SKIPPED ENTIRELY when called anywhere inside freelist_save: GC-12
      #    bars all GC draws during freelist_save; only steps 1 and 3 apply there.)
      if let Some(run) = gc_reclaim(n, oldest_reader()):
          return run

      # 3. Extend the file: hand out [next_pgno .. next_pgno+n), then
      #    next_pgno += n. Fails MapFull per GC-17.
      return extend(n)
  ```
- **GC-17 — MapFull boundary (B6 fix).** Let `map_pages = map_size / psize`; valid
  pages are `0 .. map_pages − 1`. Extending for a run of `n` pages makes the new
  high-water `next_pgno + n`. If steps 1–2 cannot satisfy the request **and**
  `next_pgno + n > map_pages` (the run would **end past** the map — equivalently its
  last page `next_pgno + n − 1 > map_pages − 1`), `allocate` fails with
  `MdbError::MapFull` (SPEC 02 §8, SPEC 00 row 55). The txn aborts cleanly with no
  partial state (SPEC 04 TXN-59). Growth beyond `map_size` is not automatic in
  Phase 1 (auto-geometry is Phase 3.2). **Worked boundary** (map_size 1 MiB, psize
  4096): `map_pages = 256`, valid pages `0..255`; with `next_pgno = 256`, a
  single-page alloc has `256 + 1 = 257 > 256` → **`MapFull`** (page 256 rejected);
  a run `next_pgno = 254, n = 2` gives `254 + 2 = 256 ≤ 256` → **allowed** (fills
  the map exactly). Same predicate as SPEC 02 §8.
- **GC-28 — extended pages durability.** Newly extended pages (allocate step 3,
  GC-16) require the file to be `≥ next_pgno * psize` bytes before the meta
  recording the new `last_pg` becomes durable; the commit pipeline guarantees this
  (dirty pages in the extended region are written and fsynced, SPEC 04 §9 C2/C3,
  **before** the meta C4), so a crash can never leave `last_pg` past the real file
  length (SPEC 06 REC-14). (Numbered GC-28 — placed here with the allocation topic
  though it is the highest id; see the count in §10.)

## §6 — Reclamation gate (oldest reader), scan, and remainder rewrite

- **GC-18 — the reuse gate + ascending scan.** A GC entry keyed by freeing-txnid
  `F` is **reclaimable** by the current write txn iff `F ≤ oldest_reader()`
  (SPEC 04 TXN-20/TXN-21; pre-M1.8 the interim reader registry of TXN-21 as
  amended by ADR-0005 OQ1). With no live readers, `oldest_reader() =
  writer_txnid − 1`, so pages freed by any *committed* txn are reclaimable.
  `gc_reclaim(n, oldest)` walks the GC DB in **ascending
  txnid** order (forward cursor from `first()`; because keys are big-endian, GC-2,
  this visits the numerically oldest freeing-txn first):

  ```
  gc_reclaim(n, oldest):
      for (F, pil) in gc_cursor.forward():
          if F > oldest: break                 # gate; no older entries remain
          if n == 1:
              p = GC-19 deterministic single-page pick from pil
              record drain(F, {p})             # remainder rewrite deferred (GC-20)
              return [p]
          else:
              if pil has a contiguous run [p .. p+n):
                  record drain(F, that run)
                  return that run
      return None                              # nothing reclaimable; caller extends
  ```

  **Freelist validation (added 2026-09-09, security review H4).** The GC DB is
  on-disk data and is **never trusted**: on first decode of an entry's PIL
  (before any id can be handed out or enter the drain pool), every id must be
  **strictly ascending** (the run-finding and drain bookkeeping binary-search
  sorted ids) and within `[FIRST_DATA_PGNO, base.last_pg]`, checked with
  overflow-safe arithmetic. A violating entry fails the allocating operation
  with `MdbError::Invalid` (corrupt freelist). Without this, a hostile PIL
  could hand out page 0/1 — the meta slots, silently clobbered at commit C2 —
  a live page, or a page past the committed file (an unbacked-map write under
  `WRITE_MAP`, or a wild `pwrite` offset). The in-save pool draw (GC-12)
  inherits the guarantee: the drain pool only ever holds validated ids. The
  page-granular I/O layer additionally computes every `pgno * page_size`
  offset checked, returning `Io(InvalidInput)` on overflow as a second line of
  defense.

  - Correctness (MVCC + crash): because `oldest_reader() ≤ N − 1`, a reclaimed page
    was freed by `F ≤ N − 1` and so is absent from the `N − 1` tree (a page freed by
    `F` left `F`'s tree and every later tree). Safe both for live readers on `≤ N−1`
    **and** for the crash fallback to `N − 1` (SPEC 04 TXN-62, SPEC 06 REC-6).
- **GC-19 — single-page-pick determinism.** When `n == 1`, `gc_reclaim` takes the
  **smallest page id** (the first, since PILs are sorted ascending, GC-4) of the
  **smallest reclaimable txnid** `F` (the first entry the forward scan reaches with
  `F ≤ oldest`). This fully determines which page is handed out, so allocation is
  reproducible run-to-run (important for the differential oracle and for
  crash-image determinism, SPEC 06 §5).
- **GC-20 — partial-drain rewrite-remainder (never literal-delete a partially
  drained entry).** Draining pages from entry `F` does **not** delete the entry
  unless *all* its ids are consumed. At `freelist_save` step (a) (`apply_drains`,
  GC-11): if a drain removed **some but not all** ids of `F`, the entry is
  **rewritten** with the remaining (still-sorted) ids as a fresh PIL under the same
  key `F`; if the drain removed **all** ids, the entry is deleted. It is never
  correct to delete a partially-drained entry (that would leak the undrained free
  pages) nor to leave a drained id in place (that would double-hand it out). The
  rewrite preserves GC-4 (sorted, unique) for the remainder.
- **GC-21 — coalescing / fragmentation policy (Phase 1: minimal).** Within one PIL,
  adjacent ids are grouped by the sorted order (GC-4), so a contiguous run is found
  by scanning. ZeroDB does **not**, in Phase 1, coalesce free ids *across* different
  txnid entries into a global contiguous-run index — that is a source of the
  huge-txn weakness (§8) and exactly what Phase 3.1 redesigns. Phase 1 policy: reuse
  single pages greedily oldest-first (GC-19); for overflow runs, take the first
  within-PIL contiguous run of sufficient length, else extend. This matches LMDB
  (and its fragmentation) for parity (PLAN 1.5 tolerance band).

## §7 — `non_free_pages_size` and `real_disk_size` (SPEC 00 rows 18/19 — MUST)

- **GC-22** — `real_disk_size()` (SPEC 00 row 18) = the actual on-disk file length
  via `fstat`, which for a whole-page file is `(last_pg + 1) * psize` (SPEC 02 §8).
  No GC walk needed.
- **GC-23** — `non_free_pages_size()` (SPEC 00 row 19, MUST) = `real_disk_size() −
  free_page_count() * psize`, where `free_page_count()` sums the page ids across
  **all** GC entries reachable from the *read txn's* `free_db.root`:

  ```
  free_page_count(rtxn):
      total = 0
      for (F, pil) in walk(rtxn.free_db):    # every entry, any txnid
          total += pil.count                 # the u64 count prefix (GC-3)
      return total
  ```
  This walk is the native replacement for milli reading LMDB's freelist (SPEC 02
  §8). It runs under an ordinary read snapshot (SPEC 04 §3), counting the **sum of
  PIL counts**, not the number of GC entries. Overflow-spilled PILs (GC-5) are read
  through their overflow run like any large value.
- **GC-24** — `non_free_pages_size()` drives milli's auto-resize trigger
  (`> 0.75 * map_size`, SPEC 00 row 19). The exact-sum walk (GC-23) is precise for
  the snapshot — no estimation — so it neither under-counts free pages (which would
  over-report usage and trigger premature resizes) nor over-counts (which would
  delay a needed resize).

## §8 — The documented huge-transaction weakness (measurable baseline for 3.1)

Phase 1 keeps LMDB's flat, txnid-keyed freelist **and its known weakness**, so
Phase 3.1 has a measured baseline (PLAN 1.5/3.1). Documented, not fixed here.

- **GC-25 — what degrades.** The GC DB is a flat map keyed by freeing-txnid with a
  per-txn PIL value. A single write txn that frees very many pages (e.g. a
  Meilisearch full reindex rewriting most of an index) produces one enormous PIL,
  which (1) **spills to a large overflow run** (GC-5) read/rewritten as a unit;
  (2) makes `freelist_save` rewrites **O(size)** — each rewrite touches the whole
  overflow value; (3) reclaims **coarsely** (GC-21): with no cross-txn contiguous-
  run index, an overflow-run allocation may fail to find a run and extend the file
  even when enough *non-adjacent* free pages exist — file growth outpaces
  reclamation under fragmented churn.
- **GC-26 — when it degrades (measurable definition, spill math corrected).** A GC
  entry's leaf cell is `8 (leaf-node header) + 8 (txnid key) + dsize`, with
  `dsize = 8 + 8c` (PIL count prefix + `c` ids, GC-3). It stays inline (SPEC 02
  §4.2) iff `24 + 8c ≤ max_node_size`, i.e. `c ≤ (max_node_size − 24) / 8`; the PIL
  **spills to overflow** (GC-5) once `c > (max_node_size − 24) / 8`. Concretely at
  `psize = 4096` (`max_node_size = 2030`, SPEC 02 §4.2): inline up to `c = 250`,
  spill at **`c ≥ 251` freed pages in one txn**; at `psize = 65536`
  (`max_node_size = 32750`): inline up to `c = 4090`, spill at **`c ≥ 4091`**.
  Beyond the spill threshold, per-commit freelist-handling cost grows with the
  freed-set size rather than staying bounded. M1.5's acceptance bench (bounded file
  growth under churn, PLAN 1.5) measures file size and per-commit GC time against
  this threshold to establish the Phase-3.1 baseline.
- **GC-27 — not fixed in Phase 1.** No mitigation is attempted (no splitting a huge
  PIL across synthetic keys, no cross-txn run index). Phase 3.1 replaces the flat
  freelist with an O(log n)-under-huge-txns structure (mdbx-inspired), ADR first.
  Phase 1's job is parity + a faithful baseline, so GC-21/GC-25 behavior is
  intentionally LMDB-shaped.

## §9 — GC check-tool invariants (continue SPEC 03 INV numbering)

The check tool (`zerodb-tools check`, M1.12) treats the GC DB as the authority for
"free" in the reachability-xor-freeness invariant. These extend SPEC 03 §11
(which ended at INV-21).

- **INV-22** — **Reachable XOR free (GC side of INV-10).** Every page in
  `[FIRST_DATA_PGNO, last_pg]` is either reachable exactly once through some DB tree
  (main, named sub-DBs, or the GC DB's own tree pages) **or** listed exactly once as
  a free page in some GC entry's PIL — never both, never neither. (GC-authority
  restatement of SPEC 03 INV-10.)
- **INV-23** — **GC key well-formedness.** Every GC entry key is exactly 8 bytes,
  decoded **big-endian** (GC-2), and every key's txnid is `≤` the live meta txnid
  (no GC entry keyed by a future txn; mirrors INV-20).
- **INV-24** — **No page double-freed.** No page id appears in more than one GC
  entry, and none more than once within a single PIL (GC-4). (Subsumed by INV-22 but
  checked directly for a sharper diagnostic.)
- **INV-25** — **Free ids in range.** Every page id in every PIL is in
  `[FIRST_DATA_PGNO, last_pg]` (SPEC 02 §7); no free id is a meta slot (0/1) and none
  exceeds the high-water.
- **INV-26** — **PIL sorted & counted.** Each PIL's `count` prefix equals the number
  of ids that follow, and the ids are strictly ascending (GC-3/GC-4).
- **INV-27** — **`non_free_pages_size` consistency.** `real_disk_size −
  non_free_pages_size == free_page_count() * psize` (GC-22/GC-23): the reported free
  bytes equal the summed PIL counts times the page size.
